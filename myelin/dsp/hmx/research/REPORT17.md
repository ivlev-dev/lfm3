# REPORT17: channel-major 1-байтовая раскладка — 32 не достигнуто

## Проверено

```
act_off(s,c) = c*32 + s        (1 КБ = 32 канала × 32 spatial, 1 байт на ячейку)
wgt_off(k,n) = k*32 + n
две пары: +0 и +512, :deep на весах, mxclracc один раз
```

| `act_rt` | `wgt_rt` | `A=1,B=1` (out[0] / out[512]) |
|---|---|---|
| 0x03C (ch_stop 15) | 1023 | 0 / 0 |
| 0x07C (ch_stop 31) | 1023 | **24 / 24** |
| 0x7FF (mask 11111 + stop 31) | 2047 | 24 / 24 |
| 0xFFF | 1023 | 24 / 24 |
| 0x03C | 1023 | 16 / 16 |

Т.е. максимум 24 (похоже 16 + 8), 32 не получается. Варианты «транспонировано»
(`wgt_off = n*32 + k`, `act_off = s*32 + c`) в этой сессии уже проверялись в
других комбинациях — все дают 16…24.

## Что зафиксировано по итогам всей серии

Измерено и воспроизводимо (REPORT1–17):
1. Питание HMX (`HAP_power_set_HMX`) — корень исходного краша CDSP.
2. VTCM: 4 МБ, MMU-адрес 0xfec00000; HMX ходит по тем же адресам.
3. Store: **одна** инструкция `mxmem(...):after…=acc` заполняет весь 2-КБ тайл
   (проверено маркером 1024/1024), spatial mask на это не влияет.
4. Bias: 32 low-word (scale fp16) + 32 high-word.
5. MAC-геометрия int8: `MAC = (stop+1)/2`; fp16 на этом устройстве ведёт себя как
   2-MAC при любых Rt.
6. Раскладки, дающие точные карты для **одного** 16-канального блока
   (`act (s>>1)*128 + c*4 + (s&1)*2`, `wgt (k>>1)*128 + n*4 + (k&1)*2`).
7. `:deep` на весах заставляет две пары складываться в acc (16+16 = 32 на одном и
   том же блоке).
8. Конфиг QNN снят статически: поля `r4+{0x00,0x04,0x08,0x18,0x30}`, deep = бит 5
   в `+0x30`; констант в бинаре нет (всё из метаданных тензора).
9. `cvt` на v68 отсутствует по ISA (v73+).
10. dlopen QNN-скелета из нашего PD запрещён (AEE_EBADPERMS).

## S1 / S4

* S1 int8 32×32×32 — **не закрыт** (лучший max_abs_err = 32; 32 MAC получались
  только как 16+16 одного блока).
* S4 128×7680×2048 — не измерялся.
* Доля от QNN (2.44 мс / 0.83 TMAC/s) — не измерена.

## Вердикт

Гипотеза channel-major не подтвердилась (24 вместо 32). За серию перебраны:
2-байтные и 1-байтные ячейки, channel-major и spatial-major, шаги 512/1024/2048,
`dC` на активации, `:deep` на весах, `:above`, `Rt` 0x3C/0x7C/0x7FF/0xFFF,
`wgt_rt` 1023/2047/4095, `mxswapacc`, `cvt` (нет на v68), прямой вызов QNN
(запрещён PD). **HMX на этом устройстве в int8 не заводится воспроизводимо.**

Единственный оставшийся достоверный путь — рантайм-дамп `r4`-слов в работающем
QNN-графе (трассировка/хук), т.к. статически констант нет, а перебор исчерпан.
Prefill — на QNN/HVX (2.44 мс / 0.83 TMAC/s), путь не блокируется.
Стенд здоров, 0 зависаний, HMX выключен.
