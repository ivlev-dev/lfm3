# hvx — HVX-ядра (Hexagon v68): GEMV, FFN, attention

Всё считается на CDSP в одном FastRPC-вызове на слой; веса живут на DSP
резидентно. Стенд не требует устройства для сборки, но все цифры — с телефона.

## Сборка и запуск

```bash
HEXAGON_SDK_ROOT=/path/to/Hexagon_SDK/6.7.0.0 ./build.sh
export MADB=<adb-серийник>
./run.sh push
./run.sh lfmgemv_test                 # GEMV: корректность + полоса
./run.sh ab_test 3 3                  # A/B варианты: раунды, повторы
./run.sh ffn_test 2 2                 # FFN-слой, 2 контекста
./run.sh ffn_test 2 2 - 1             # FFN-слой на одном контексте (без team)
./run.sh ffn_test 2 2 scal            # то же со скалярной SiLU (A/B)
./run.sh ffn_test 2 2 prof            # + профиль SiLU по шагам
./run.sh ffn_test 1 1                 # 1 раунд sweep, 1 токен
./run.sh attn_test 64 0 2             # ctx 2048, полное окно, 2 контекста
./run.sh attn_test 64 0 1             # то же на одном контексте (эталон времени)
./run.sh attn_test 64 256 2           # скользящее окно 256
./run.sh attn_test 64 0 2 pwl         # exp кусочно-линейный вместо bit-trick
ATTN_TRACE=1 ./run.sh attn_test 64 0 2   # плюс кольцо шагов воркера
```

`build.sh` собирает скелет (`-mv68 -mhvx -mhvx-length=128b`) и хостовые тесты
(NDK r27c, API 31). Тесты включают unsigned PD сами; скелет подхватывается через
`ADSP_LIBRARY_PATH` (его выставляет `run.sh`). `attn_test` проверяет cos с тем же
числом контекстов, что и тайминг (раньше корректность всегда шла на одном).

Офлайн-числодробилки собираются обычным `cc`, например:
`cc -O2 silu_study.c -lm -o silu_study`.

### Численность FFN без устройства

`build.sh` дополнительно собирает `ffn_sim` и `ffn_real_study` (обычный `cc`):

```bash
./ffn_sim 8                                    # синтетика: SIM OK / SIM FAIL
./ffn_real_study ../../../models/LFM3-1.7B-Q4_K_M.gguf 8
```

Масштабы в стенде — те, что реально ждут ядра: gate/up получают
`sa = 65536*s_in, so = 1`; `s_mid = absmax(P)/127` из фактического диапазона
`P = silu(gate)*up`; `s_out = max_r(sw_d*s_mid*acc_max[r])/110` (то же правило,
что в `conv_sim`). `ffn_sim` падает, если буфер mid вырожден (`|zg| < 1024`
единиц Q16), если cos(out) < 0.99, или если регресс-гейты не отбраковали
старые форматы.

Де-квант gate/up масштабируется по динамическому диапазону, а не клампится.
`m = sw*sa/so` — физическое отношение `gate/acc`, умноженное на 2^16; для
реальных тензоров LFM3 per-row int4/int8 оно равно 6..215 (int4) и 0.3..12
(int8), то есть Q16-множитель упёрся бы в clamp 0.99997, а Q30 в int32 не
влезает уже при m > 2. Ядро хранит `qm = Q16.16(m/2^k)` и берёт произведение
в 64 битах:

```
z = (acc*qm + 2^15) >> 16 = acc*m/2^k = g*2^(16-k)     (deq_wide)
k = min{ k : 127*|w|max*K*mmax/2^k <= 2^30 }            (deq_shift_for)
```

`silu_qk(z, k)` принимает Q(16-k) (при k = 0 бит-в-бит равен `silu_q16`);
`prod_p` умножает Q16 SiLU на Q(16-k) up в 64 битах. На тензорах LFM3
`k = 0` (int4: 2.1e6*216 = 4.5e8 < 2^30), запас по int32 — двукратный; сдвиг
нужен только для матриц с ещё большим `m`. Правило выбора и хост-зеркало —
в `ffn_ref.h`; то же в `myelin/dsp/conv/lfmgemv_impl.c`.

`ffn_real_study` прогоняет все 24 слоя LFM3 (int8 и int4) с реальными входами
полного f32-форварда, печатает cos/LSB/насыщение по слоям и регресс-гейты:
старый Q16+clamp и старый беззнаковый `mulq16` обязаны провалить порог.

## Формат весов int4

Row-major `[N][K]`, `K/2` байт на строку, два signed int4 в байте:

```
byte = lo | (hi << 4)        lo -> чётный k, hi -> нечётный k
хранимый ниббл = w_signed + 8    (offset-8, 0..15)
```

Коррекция скалярная, раз на строку: `sum(w*a) = sum(u*a) - 8*sum(a)`.
Активации int8 `[M][K]`, деинтерлив в `ae`/`ao` (чётные/нечётные k). Выход int8
`[M][N]` с Q16-множителем на строку (`vmpyiewh` → clamp ±127) либо сырой int32.

## Ядро GEMV (M=1, K=2048)

На строку (1024 Б = 8 HVX-векторов): `vand 0x0f` → младшие нибблы, `vlsr 4` →
старшие (2 оп/вектор); `vrmpyacc` unsigned×signed по `ae`/`ao` (2 оп/вектор);
4 аккумулятора, дерево, `-8*sum(a)`; `l2fetch` на 32 КБ вперёд (дефолт)
каждые 8 строк; дефолт — 2 строки за итерацию (3+ не реализованы).

### SiLU на HVX (бит-в-бит)

Векторный путь включён по умолчанию, `probe(45, 0)` возвращает скалярную
цепочку для A/B (`ffn_test 2 2 scal`), `ffn_test 2 2 prof` печатает профиль.

**Профиль скалярной цепочки** (`probe 40`, 7680 дорожек, pcycles, снятие шага
по одному — сумма больше полного времени, потому что вместе с шагом уходит и
часть зависимой цепочки):

| шаг | цена | cyc/дорожка |
|---|---|---|
| полная цепочка | 541–564 тыс. | **70–73** |
| LUT-1025 + lerp | 202–222 тыс. | 26–29 |
| `prod_p` (int64) | 97–98 тыс. | 12–13 |
| `requant_mid` (int64) | 92–120 тыс. | 12–16 |
| `deq_wide` ×2 (int64) | 155–160 тыс. | 20–21 |

То есть дорогие — три 64-битных произведения и округления в них
(≈45–49 cyc/дорожка), а не формула SiLU (26–29).

**Что векторизовано.** На v68 нет ни `Q6_Vd_*` (64-битных векторных
операций), ни 32×32→64; есть только 32×16→32 (`vmpyie` / `vmpyieacc` с
signed-полусловом). Поэтому каждое произведение раскладывается на четыре
16×16-частицы, которые остаются в int32:

```
a = ahi*2^16 + alo,  b = bhi*2^16 + blo      (ahi/bhi signed, alo/blo unsigned)
a*b = ahi*bhi*2^32 + (ahi*blo + alo*bhi)*2^16 + alo*blo
(a*b + r) >> 16 = (ahi*bhi)<<16 + cross + ((alo*blo + r) >> 16)
```

`ahi*bhi` — одно `vmpyieacc`, `cross` — два `vmpyie`, `alo*blo` — одно
`vmpyie`; `alo*blo` точно влезает в **unsigned** 32 бита (прибавка `r` не
переполняет), поэтому младшая часть сдвигается логически (`vlsr`). `requant_mid`
переписан как `((pr*mq)>>16 + 2048) >> 12` (вложенные floor-сдвиги равны
`(pr*mq + 2^27)>>28`), это экономит один 64-битный продукт. `silu_q16`
остаётся скалярным по дорожкам (см. ниже), но clamp и `off = z + 8*65536`
считает вектор.

Точность: `deq_wide`/`prod_p`/`requant_mid`/`silu_q16` дают **тот же int32**,
что и 64-битные формулы, пока `|a*b| <= 2^45` (иначе частичные произведения
выходят за int32). Это проверяется на живых буферах (`silu_vec_guard`:
max|acc|, max/min qm, оценка сверху для `|pr|`) и при нарушении весь диапазон
считается скалярно; на всех слоях LFM3 условие проходит с запасом ~5×.

**LUT.** `vgather` в v68 ISA есть и компилируется, но в этом unsigned PD
падает precise exception с собственным базовым адресом в `Bad VA` — проверено
и на записываемой статической таблице, и на rodata, обе выровнены на 128 Б;
`silu_lut` дополнительно выровнен, не помогло. Векторного float на v68 нет,
поэтому выборка остаётся скалярной: копия таблицы с сентинелом в `[N]`
(убирает ветку `idx >= N-1`) и `off`, посчитанный вектором. Итог — 10–14
cyc/дорожка против 70–73 скалярно, **5.2–6.9×**.

**Бит-в-бит.** `probe 44` в конце `ffn_test`:
`mul_rnd 0/2048`, `mul_floor 0/2048`, `LUT 0/131200` (все 1025 узлов ±1 и
+1023), `chain 0/46080` (6 шаблонов по 7680: полное насыщение в обе стороны,
`up < 0` во всех дорожках, около-нулевые значения, `|gate|` на границе clamp
LUT, реалистичный диапазон, малый `up` при большом `gate`), fallback 0/6.
Плюс штатные `mid 0, out 0` на 2 токенах и `ffn_sim` SIM OK.

**Время** (`ffn_test 2 2`, 5 прогонов, медиана): silu **0.07** мс против
**0.25** (2 ctx, −72 %), **0.13** против **0.66** на одном контексте (−80 %);
слой DSP 1.30 против 1.51 мс, wall 1.58 против 1.81 мс; `team_fallbacks=0`.
Смета токена = DSP-ядро + 0.18 мс RPC на слой: было
24·1.69 + 11·0.84 + 13·0.74 = **59.4 мс** (16.8 tok/s), стало
24·1.48 + 11·0.84 + 13·0.74 = **54.3 мс** (18.4 tok/s).


## Что важно знать (иначе теряется день)

- **`qurt_thread_create` с HVX-функцией возвращает −1**, пока не задан явный
  адрес стека (`qurt_thread_attr_set_stack_addr`) — как в `libs/worker_pool`.
  Этот PD отдаёт 2 HVX 128B-контекста; `qurt_hvx_reserve` возвращает −1.
  Воркеры берут HVX-лок на задачу (держать контекст всю жизнь потока — дедлок).
- **`mulq16(a,b)` = `(a*b)>>16` в int32** — 64-битные хелперы на v68 дороги.
- **`pack_out_i8` — HVX** (`vmpyie 32×16` + `asr` + `vmax/vmin` + `vpack`,
  128 выходов за итерацию). Бит-в-бит равен 64-битной формуле, пока
  `max|acc|*max q <= 2^30`, иначе — скалярный 64-битный путь. Прежний
  скалярный цикл стоил 58 мкс на N=2048 (24 % in_proj в `../conv`).
  `Q6_Vw_vmpyieacc_VwVwVuh` для этого не годится — даёт неверные лейны.
- **`run_split_m1`: две гонки закрыты** квитанциями `seq`/`done_seq`,
  `__sync_synchronize()` перед публикацией задания и `qurt_mem_syncht()`
  в воркере перед `done_seq`. Симптом до фикса: первый GEMV после
  `team_start()` в 25 % прогонов терял половину диапазона, а рабочий мог
  прочитать предыдущее задание (указатель `acc` другого буфера).
  Ограниченный спин в `team_join()` пересчитывает диапазон на главном потоке
  и считает такие случаи (`times[8]` FFN, во всех прогонах 0).
- **SiLU**: LUT-1025 + lerp даёт max|err| 3e-5 (Q16); кусочно-квадратичная
  32 сегмента — 3e-4; единый полином deg 13/17 — 1.8e-2/4.4e-3 и переполняет
  16×16. В v68 нет HVX-float; `vgather` в ISA есть, но в этом PD падает
  (precise exception, `Bad VA` = собственный базовый адрес, и для rodata, и для
  записываемой таблицы). Рабочий путь — «вектор всё, кроме LUT»: три int64-
  умножения через разложение на 16×16 (см. раздел про SiLU), 10.3–13 cyc/дорожка
  против 71–73 скалярно, бит-в-бит.
- **Paged attention**: page = 32 токена, `slot = (tbl[pos>>5]<<5) | (pos&31)`,
  K int4 (64 Б/токен, offset-8, lo = чётная размерность), V int2
  (в тесте деквантуется хостом в int8: на DSP нет `Q6_Vh_vshuff_VhVh`).
  score в Q8, exp по умолчанию — bit-trick `exp2`, кусочно-линейный
  (`attn_test ... pwl`) даёт mean|err| 1.7e-2 против 8.1e-4 у bit-trick.
- **Attention на 2 контекстах падал с `rc=78`** на первом же задании. Причина —
  не разделяемая память и не `qurt_hvx_lock` в главном потоке (обе гипотезы
  проверялись и не помогали), а публикация задания: воркер читал `kind`,
  `r0/r1` и `ctx` (адрес стекового `actx_t`) до барьера и работал с чужим
  указателем/диапазоном. Квитанции `seq`/`done_seq` из `run_split_m1`
  (часть 1) закрывают и attention. Проверено обратным экспериментом: убрать
  ожидание `seq` в воркере — `rc=78` возвращается; убрать прогрев команды —
  всё равно PASS, то есть лечит именно квитанция.
  Кольцевой буфер шагов (`atr()`: publish → wake → hvx_lock → pass1 → pass2
  → syncht → unlock → done_seq → sem_up → join) отдаётся probe kind 31/32 и
  печатается только при ошибке или `ATTN_TRACE=1`.
- **PV token-major**: V лежит транспонированно по 32-токенной странице
  (`byte 4*d'+j = V[32g+d'][32c+j]`), один `vrmpy` на (группу dim, 4 токена),
  естественный порядок без перестановки; нормализация — `2^28/L` один раз на
  голову, int64-умножение.
- **Резидентный выход**: `lfmgemv_attach_out(h, fd, nbytes)` мапит host
  rpcmem/ION fd через `apps_mem_share_map()`, `gemv_resident`/`ffn_resident`
  пишут сразу туда. Компилируется; на устройстве не замерялось.
- RPC-стоимость: ~0.15 мс базовая, +0.4–0.45 мс при возврате 7.7 КБ;
  rpcmem/ION для этого не помогли.
