# conv — depthwise shortconv (k=7) на HVX

Слой `bcx = in_proj(act)`, `y = c * depthwise_conv(bx)`, `out = out_proj(y)`
на int8/int4, состояние — 6 предыдущих токенов на канал. Плюс офлайн-симулятор,
который проверяет саму арифметику без устройства.

**Текущее состояние: симулятор FAIL по калибровке.** Это известное состояние,
ядро перенесено как есть; см. «Статус».

## Файлы

| файл | что |
|---|---|
| `lfmgemv.idl` | FastRPC-интерфейс, включает `conv_init`/`conv`/`conv_reset`/`conv_free` |
| `lfmconv_impl.c` | DSP-ядро слоя: квантование весов, 8-слотовое кольцо, hi/lo-плоскости |
| `lfmgemv_impl.c` | GEMV/FFN/attention-часть стенда (своя копия, не из `../hvx`) |
| `conv_math.h` | целочисленная математика: `conv_K`, `conv_make_kq`, `conv_ring_slot` |
| `conv_ref.h` | f32-эталон, int8 shift-register и точная модель DSP-кольца |
| `conv_sim.c` | офлайновый симулятор (хост, без SDK и устройства) |
| `lfmconv_bridge.h`, `silu_lut.h`, `exptab.h` | вспомогательные заголовки |
| `build.sh` | `conv_sim` (host cc) + DSP-скелет (hexagon-clang) |

`lfmgemv_impl.c` здесь — отдельная копия с более ранним состоянием attention
(`g_attn_tm = 1`, без local-context job), поэтому стенд самодостаточен и не
тянет `../hvx`.

## Сборка

```bash
HEXAGON_SDK_ROOT=/path/to/Hexagon_SDK/6.7.0.0 ./build.sh   # + ANDROID_NDK_ROOT при нужде
./conv_sim                    # офлайн, по умолчанию H=2048, ntok=12
./conv_sim 2048 12
```

Скрипт собирает `conv_sim` обычным `cc` (SDK не нужен), генерирует qaic-файлы и
собирает `liblfmgemv_skel.so`. Host-драйвер `conv_test` собирается только если
рядом есть `conv_main.c` — в репозиторий он не переносился (в исходной среде
его уже не было), поэтому **на устройстве этот стенд сейчас не запускается**.

## Статус (воспроизводится `./conv_sim`)

```
ring/phase vs shift register: 0 mismatches out of 24576
out_proj multiplier m: min=0.015 max=0.018   (must be <=1 for Q16)
bcx multiplier       : min=0.001 max=0.002
int8 saturation: bcx=0.05%  y=3.35%  out=63.81%
worst: cos(out)=-0.174034  maxerr(out)=0.14772  cos(y)=0.071224
SIM FAIL
```

Что это значит:

- **Кольцо/фазы на DSP смоделированы верно** — 0 расхождений с наивным
  shift-register на 24576 значениях.
- **Провал — в калибровке масштабов**, а не в ядре: `s_out` выбирается от
  absmax выхода (0.069), из-за чего `out` уходит в saturate на 64% ячеек, а
  cos(out) падает до отрицательных значений. Виновник — `out_proj`:
  per-row множители 0.015–0.018 при допуске ≤1 (Q16), т.е. выходной тензор
  квантован слишком мелко относительно входа.
- `y` (промежуточный) сатурируется на 3.35% — уже заметно, но не фатально.

Следующий шаг — чинить выбор `s_bc`/`s_y`/`s_out` (калибровка по перцентилю или
от `s_w_out`, а не от absmax реального выхода), затем вернуть host-драйвер и
мерить на устройстве.

При переносе в `conv_sim.c` исправлены две строки, обращавшиеся к
несуществующему `m.cw.srow[r]` (структура `cw` — это `float*`): теперь
используются `m.sw_out[r]`/`m.sw_in[r]`, как в `conv_ref.h`. Вывод симулятора
совпадает с сохранённым бинарником из исследовательской среды.
