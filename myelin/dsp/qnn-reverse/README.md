# qnn-reverse — реверс QNN-скелета QnnHtpV68Skel

Разбор бинарника/заголовков QNN HTP: как устроены int8-кроутоны HMX, какие
control-слова (`Rt`) ожидают ядра, что реально исполняется на v68.

Ключевые выводы (полностью — в `REPORT.md`):

- Проверенная геометрия fp16: `addr16(s,c) = (s>>1)*128 + 4*c + 2*(s&1)`.
  Ходовая формула `(s>>1)*128 + (s&1)*64 + (c>>4)*32 + (c&15)*2` **неверна** —
  она тождественна плоскому `64*s + 2*c`.
- int8 (A8W8, `activation.ub`, без `:cm`): `addr8(s,c) = (s>>2)*128 + 4*c + (s&3)`,
  s=0..63, c=0..31 (2 КБ).
- Один multiply-pair на v68 int8 = 64 spatial × 32 N × 32 K = 65536 MAC,
  а не 16 MAC.
- `:deep` на активации — накопление по K (dC+1 кроутонов, до 32 → K до 1024);
  `:deep` на весе — 2 КБ весов = 64 выходных канала и два банка аккумулятора.
- На v68 нет `cvt.*` (v73+); вместо них слитный `mxmem(Rs,Rt):after.<fmt> = acc`.
- У int8-ядра QNN (`bbb`) на v68 deep нет — заглушка `r0=-1`; deep только у
  hbh/hnh (16-битный выход).

`REPORT.md` ссылается на `/tmp/opencode/qairt` и `layout_test2.cpp` из исходной
исследовательской среды. Сам `layout_test2.cpp` (проверка `memory_layout.h`) в
репозиторий не переносился — это одноразовая проверка формулы.

Практический результат реверса — рабочий int8-рецепт в `../hmx` (см.
`research/REPORT18.md`).
